# ตารางการทำงานแพทย์ ศูนย์เอราวัณ

Google Apps Script สำหรับดูและบันทึกตารางงานแพทย์ จัดการตารางผู้มาฝึกงาน และส่งอีเมลสรุป ใช้ Google Sheets เก็บข้อมูล และเปิดฟอร์มได้ทั้งจาก Web App และแถบด้านข้างในชีต

## ไฟล์ในโครงการ

| ไฟล์ | หน้าที่ |
| --- | --- |
| `src/Code.gs` | อ่านและเขียนข้อมูล จัดกลุ่มตาราง สร้างชีตปฏิทิน และส่งอีเมล |
| `src/Index.html` | หน้าตาราง ฟอร์มเพิ่มและแก้ไขรายการ และหน้าส่งออก |
| `src/appsscript.json` | การตั้งค่าพื้นฐานที่จัดทำสำหรับโครงการสำเนา ใช้ V8 และเขตเวลา Asia/Bangkok |

สำเนานี้อ้างอิงจากไฟล์ GAS และ HTML ที่ส่งออกไว้บนเครื่อง ชื่อที่ใช้เติมชีต Staff ครั้งแรกถูกแทนด้วยชื่อสมมติ การตั้งค่าของ deployment และข้อมูลในชีตจริงต้องตรวจจากโครงการที่ใช้งานอยู่

## ตารางมาจากไหน

| ชีต | ข้อมูล |
| --- | --- |
| Staff | รายชื่อ บทบาท อีเมล สถานะ Active และลำดับแสดงผล |
| Schedule | งานหนึ่งรายการต่อหนึ่งแถว ระบุวันที่ ผู้รับงาน ช่วงเวลา กิจกรรม หมายเหตุ ผู้บันทึก เวลาบันทึก สถานที่ และประเภทการประชุมเมื่อเปิดใช้ |
| Trainee | ผู้มาฝึกงานตามวัน ประเภท สถาบัน จำนวนและหมายเหตุ |
| Config | ผู้รับอีเมล ตำแหน่งลิงก์ Web App และชั่วโมงส่งอีเมล |
| Calendar | ตารางจันทร์ถึงศุกร์ที่ระบบสร้างใหม่จากข้อมูลต้นทาง |

หน้าเว็บเรียก `apiGetMeta` เพื่อโหลดรายชื่อและตัวเลือก จากนั้นเรียก `apiGetWeek` หรือ `apiGetMonth` ผ่าน `google.script.run` มุมมองรายสัปดาห์แสดงจันทร์ถึงศุกร์เป็นการ์ดรายวัน มุมมองรายเดือนวางชื่อบุคลากรตามแถวและวันที่ตามคอลัมน์ แสดงเช้าและบ่ายด้วยสี สื่อสถานที่และการลา และกดเปิดรายละเอียดวันได้ วันเสาร์และอาทิตย์ที่ไม่มีรายการถูกซ่อนในมุมมองรายเดือน ส่งออกได้เป็น JPEG หรือพิมพ์เป็น PDF โดยเลือกทั้งตารางหรือเฉพาะบุคคล

ฟอร์มเพิ่มงานเรียก `apiSaveScheduleBulk` เพื่อบันทึกหลายคนและหลายวัน โดยสร้างหนึ่งแถวต่อคนต่อวันและมีตัวเลือกแจ้งอีเมล การแก้ไขและลบใช้ ID ของรายการ ฟอร์มผู้มาฝึกงานเขียนลงชีต Trainee ผ่านชุดฟังก์ชันของตนเอง ระบบเดิมตั้งตัวเรียกอัตโนมัติให้สร้าง Calendar ทุกชั่วโมงและส่งอีเมลสรุปตาม Config

## สิ่งที่ควรตรวจในชีตสำเนา

1. `sheet_` ใช้ `getActiveSpreadsheet()` ซึ่ง Google ระบุว่าใช้ไม่ได้เมื่อเรียกสคริปต์ที่ผูกกับชีตในฐานะ Web App หรือผ่าน Apps Script API ตรวจเวอร์ชันที่ deploy จริงและปรับให้เปิดชีตตาม ID จาก Script Properties สำหรับช่องทางที่ต้องเรียกจากภายนอก [เอกสาร Google](https://developers.google.com/apps-script/guides/bound)
2. สรุปวันพรุ่งนี้อ่านตารางตามวันที่พรุ่งนี้ในเขตเวลา Asia/Bangkok โดยตรง กรณีพรุ่งนี้เป็นเสาร์หรืออาทิตย์จะเว้นอีเมลถ้าวันนั้นไม่มีรายการงานและผู้มาฝึกงาน
3. ตรวจสิทธิ์ของ deployment และเพิ่มการตรวจสิทธิ์ในฟังก์ชันเพิ่ม แก้ไข และลบที่ฝั่งเซิร์ฟเวอร์ โค้ดเดิมตรวจผู้ดูแลในส่วนจัดการรายชื่อ ส่วนการลงรายการใช้บัญชี Google ที่มองเห็นได้หรือบันทึกเป็น `anonymous`
4. ชื่อใน Schedule เชื่อมกับ Staff ด้วยข้อความตรงกัน ควรให้ผู้ใช้เลือกจากรายชื่อที่ตรงกันเมื่อพบชื่อย่อหรือชื่อคลุมเครือ และป้องกันรายการซ้ำเมื่อส่งคำขอเดิมอีกครั้ง

เมื่อต้องทดสอบกับ Google ให้สร้างสำเนาชีตและผูก Apps Script กับสำเนา ใช้ชื่อไฟล์ `Code.gs` และ `Index.html` ตามโครงการ ตั้งเขตเวลาให้ตรงกัน และตรวจการตั้งค่าของโปรเจกต์เดิมก่อนซิงก์ด้วย clasp เรียก `setup()` จากโครงการที่ผูกกับชีตเพื่อสร้างโครงสร้างบนชุดทดสอบ ตรวจผู้รับก่อนเปิดอีเมล และตรวจตัวเรียกอัตโนมัติเดิมก่อนใช้ `setupTriggers()` ซึ่งลบตัวเรียกที่มองเห็นในโครงการก่อนสร้างชุดใหม่ [คู่มือ clasp](https://developers.google.com/apps-script/guides/clasp)

### ทดสอบระยะ 1 บนชีตสำเนา

เทียบชื่อแท็บและแถวหัวคอลัมน์กับค่าคงที่ `SCHEDULE_HEADER`, `STAFF_HEADER`, `TRAINEE_HEADER` และ `CONFIG_HEADER` ในโค้ดก่อนทดสอบ สำหรับสำเนาที่มีข้อมูลแล้ว ให้เรียก `setupMeetingTypes()` จาก Apps Script ของสำเนา ฟังก์ชันนี้เพิ่มคอลัมน์ `MeetingType` ต่อจาก `Location` และตั้งรายการเลือก โดยใช้ข้อมูลเดิมใน `Staff` และ `Schedule`

ตรวจไฟล์ Excel ที่ส่งออกจากชีตหลังบ้านแล้ว พบแท็บที่ระบบใช้ครบและหัวคอลัมน์ทั้งสี่แท็บตรงกับโค้ด `Schedule` สิ้นสุดที่ `Location` ในคอลัมน์ I จึงมีคอลัมน์ J สำหรับ `MeetingType` ทดสอบการเพิ่มคอลัมน์ เพิ่ม แก้ไข และลบงาน และเนื้อหาอีเมลกับข้อมูลจากไฟล์สำเนาบนเครื่องแล้ว ก่อนใช้กับชีตจริงให้ตรวจการทำงานใน Google Apps Script บน Google Sheets สำเนาตามขั้นตอนด้านล่าง

เพิ่มประเภทประชุมในเอราวัณประจำและไม่ประจำ นอกเอราวัณประจำและไม่ประจำ และออนไลน์ประจำ ประเภทที่เลือกจะกำหนดสถานที่ให้ตรงกัน รายการทั่วไปใช้ตัวเลือกสถานที่เดิม คำว่า “ประจำ” เป็นประเภทการประชุมในระยะนี้

1. บนชีตสำเนา ทดลองรัน `setupMeetingTypes()` สองครั้งแล้วตรวจว่าคอลัมน์ใหม่มีเพียงหนึ่งคอลัมน์ และข้อมูลเดิมอยู่ครบ
2. จาก Sidebar ของสำเนา เพิ่มประชุมทั้งห้าแบบและงานทั่วไป ลองเพิ่มหลายคนหลายวัน แก้ประเภท แล้วลบรายการทดสอบ ตรวจค่า `Location` และ `MeetingType` และตรวจตารางสัปดาห์กับเดือน
3. ทดสอบอีเมลด้วยการเรียก `tomorrowDigest_(new Date('2026-11-17T10:00:00Z'))` จากฟังก์ชันทดสอบชั่วคราวใน Apps Script ของสำเนา ผลควรเป็นวันที่ 18 พฤศจิกายน 2569 และมีเฉพาะรายการของวันนั้น ให้เปรียบเทียบกับวันจันทร์ในสัปดาห์เดียวกัน และทดสอบเสาร์–อาทิตย์ทั้งวันที่มีรายการและวันที่ว่าง ฟังก์ชันนี้สร้างเนื้อหาอีเมลโดยไม่ส่ง
4. รัน `node --test tests/schedule.test.cjs` เพื่อตรวจพฤติกรรมซ้ำด้วยข้อมูลจำลอง

## แนวทางเชื่อมแชตในระยะถัดไป

- ให้หน้าเว็บและช่องทางแชตใช้ขั้นตอนเขียนตารางร่วมกัน โดยรับวันที่เริ่มและสิ้นสุด ผู้รับงาน ช่วงเวลา กิจกรรม สถานที่ และหมายเหตุ พร้อมระบุตัวผู้บันทึกจากช่องทางต้นทาง
- ตัวอย่างข้อความ “เพิ่มงานแพทย์ตัวอย่าง 1 พรุ่งนี้เช้า ประชุมนอกสถานที่” ให้ระบบแปลง “พรุ่งนี้” ตามเวลาไทย แสดงวันที่จริงและรายละเอียดเพื่อยืนยันก่อนบันทึก ถ้าชื่อหรือวันไม่ชัด ให้ถามกลับ
- หากเริ่มจาก LINE ใช้ตัวรับ webhook ที่อ่านส่วนหัว `x-line-signature` ได้ ตรวจลายเซ็นกับข้อความดิบ ตรวจสิทธิ์ของ LINE user ID และใช้ `webhookEventId` สำหรับจับการส่งเหตุการณ์ซ้ำ เอกสาร Apps Script ไม่ระบุช่องสำหรับอ่านส่วนหัว HTTP ในออบเจ็กต์ `doPost(e)` จึงควรแยกตัวรับ LINE ออกจาก Web App เดิม [LINE Developers](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/) · [การส่ง webhook ซ้ำ](https://developers.line.biz/en/docs/messaging-api/receiving-messages/#webhook-redelivery) · [Apps Script Web Apps](https://developers.google.com/apps-script/guides/web)
- หากเริ่มจาก DOT ให้ยืนยันก่อนว่าเป็นบริการใดและมีช่องทางเรียกการบันทึกแบบยืนยันตัวตนอย่างไร แล้วจึงต่อเข้ากับขั้นตอนตรวจและบันทึกเดียวกัน
